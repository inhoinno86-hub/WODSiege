# Step 04 — Android 빌드·통합 검증·인수

## 목표와 기준

main 기준 02/03 통합 결과를 실제 명령과 화면으로 검증한다. intent의 W-10과 검증 조건, 원본 §11/14를 읽는다.

## 실행 지시

1. Capacitor Android 프로젝트를 생성·동기화하고 위치 권한·기기 크기 변경·디버그 서버 접속을 설정한다.
2. Android 도구가 없으면 프로젝트 전용 `.tools/`에 공식 배포 도구를 설치해 debug APK 빌드를 시도한다. 인증이나 시스템 전역 설정을 변경하지 않는다.
3. 서버·단위 테스트, TypeScript/앱 빌드, Playwright 통합·리사이즈 검증을 실행하고 실패를 수정한다.
4. UI 스크린샷을 점검한다. USB 기기가 없으면 실기기 통과를 주장하지 않는다.
5. README, `docs/ANDROID-TESTING.md`, `docs/IMPLEMENTATION-STATUS.md`에 시작·설치·API·개발 정책·남은 공개 요건 및 실행 증거를 남긴다.
6. diff와 ignore 상태를 확인하고 main Progress log를 실제 결과로 갱신한다.

## 제약·산출물

커밋·push·배포·스토어 공개는 하지 않는다. 키/사용자 영상/DB는 git 제외. 실기기 결과와 브라우저 결과 구분. 산출물 Android 소스·가능 시 APK·검증 테스트·안내 문서.

## 완료 기준

- 실행한 테스트와 빌드의 실제 결과를 기록한다.
- 개인/팀 경기, 양 장소 방식, 취소/분쟁/정정·원장을 통합 검증한다.
- 360/412/840px 화면, 입력 유지, 오류 처리 검증.
- APK 설치 경로 또는 명확한 빌드 장애와 재현 방법 제공.
- W-01~10 상태와 외부 조건을 정직하게 인계한다.
