# 후속 작업: 기기·운영·복구·배포 준비 현황

기준일: 2026-09-06. 사용자 요청: 앱 설명서의 다음 작업을 진행하고 작업별 적절한 모델·추론 수준의 하위 에이전트에 배정.

## 결론

로컬에서 진행할 수 있는 기기 사전 점검, 백업/새 경로 복구 도구, HTTPS 배포 설정과 서버 입력 검사, 운영 승인 준비서를 추가했다. **Fold7 실기기 인수·운영 정책 승인·실제 서버 공개까지 끝낸 것은 아니다.** 연결 기기가 없고 도메인·배포 계정·비용·운영 책임자가 아직 제공/승인되지 않은 항목은 아래에 구분한다.

재개 작업에서 운영자 비밀번호 변경 도구의 입력 처리와 사용 안내를 마무리하고 로컬 검증을 갱신했다. 이전 작업의 모델 배정은 아래에 보존하며, 이번 재개 작업은 주 에이전트가 코드 검토·수정·검증했다.

## 추가된 실행 명령

```bash
npm run android:preflight
npm run data:backup -- --source ./data --target ./backups/NEW
npm run data:verify -- --source ./backups/NEW
npm run data:restore -- --source ./backups/NEW --target ./data-restored-NEW
```

백업 부모 폴더는 사전 준비가 필요하다. 위 backup/restore 예시는 기본 dry-run이며 backup dry-run은 실제 백업을 만들지 않으므로 verify/restore는 **실제로 생성 완료한 백업**에 대해서만 실행한다. 쓰기는 [복구 안내](BACKUP-RESTORE.md)를 읽고 서버 중지를 확인한 뒤 `--execute --server-stopped`를 추가한다. 실제 앱 데이터에 대한 백업·복구·삭제는 이번 검증에서 실행하지 않았다.

`backups/`, `data-restored-*/`, `artifacts/`, `.env` 등 로컬 자료는 Git 제외 대상으로 관리한다. 임의의 다른 백업 경로까지 자동으로 제외하는 것은 아니므로 운영 백업과 비밀 파일은 저장소 밖의 접근 제한 경로에 보관한다.

`npm run operator:rotate -- --help`로 운영자 비밀번호 변경 옵션을 확인한다. 기본은 dry-run이며 실제 변경에는 백업 검증과 서버 정지 확인이 필요하다. [운영자 변경 안내](OPERATOR-PASSWORD.md)에 비밀 파일·세션 무효화·변경 후 재로그인 확인 절차를 정리했다.

## 동작·호환성 변화

- 개발용 로컬 실행 및 기존 경기/채점/포인트 정책은 유지한다. UI·Android 자산은 바꾸지 않아 기존 0.1.0 APK를 그대로 사용한다.
- production은 명시적인 HTTPS public origin·절대 저장 경로·proxy 접근 가능한 host·secret 파일을 요구한다. 실패 시 설정값의 비밀 내용을 출력하지 않고 시작을 거부한다.
- 허용되지 않은 Origin이 있는 요청은 OPTIONS뿐 아니라 실제 요청도 403으로 거부한다. Origin이 없는 요청은 허용하되 기존 인증·권한 확인을 계속 적용한다. 이는 로그인이나 실제 사용자 검증을 대체하지 않는다.
- 프록시 신뢰는 개발 모드에서는 꺼져 있고 production에서는 단일 비공개 프록시 한 홉을 전제로 한다. API를 직접 공개하거나 프록시 경로를 바꾸면 이 가정이 깨지므로 재검토해야 한다.
- SQLite 앱 스키마/원본 상태를 초기화하지 않았다. 복원 도구가 만든 **새 복원본의 sessions만** 비운다. 모든 기존 사용자는 복원 환경에서 다시 로그인해야 한다.
- 백업 manifest와 복원 영수증, 기기 검사 보고서는 새 운영용 파일 형식이다. 앱의 경기 기록을 대체하지 않는다. 해시는 손상 검사용이지 악의적인 백업 변조를 증명하는 서명이 아니다.

## 운영 준비에서 확인한 중요 제한

[PILOT-OPERATIONS.md](PILOT-OPERATIONS.md)에 실제로 보관·전달하는 항목과 운영 절차를 정리했다. 특히 현재 로그인 사용자에게 전체 회원의 이름·소속·역할 목록과 Box 회원/현장 확인 목록이 제공된다. 영상·원시 좌표가 제한된다는 이유로 모든 사용자 정보의 공개 범위 검토가 끝났다고 간주하지 않는다.

보관 기간·자동 삭제·탈퇴/관리자 양도·미성년자 조건·본인 확인·위치 위조 대책·코치의 과제 승인·실제 운영 인력은 미완료다. 임의의 보관 기간을 정해 기존 영상을 지우거나 운영 승인 없이 경기 규칙을 바꾸지 않았다.

- `npm run test:e2e`: 재개 검증 8/8 통과, 36.1초. 개인/팀·가입/소속·영상·분쟁/정정·화면 폭 회귀 확인.
- 실제 기기 사전 검사: `BLOCKED_NO_DEVICE`, 보고서 종료 코드 11, adb 기기 수 0. 기존 APK SHA-256 `f1279b91bdcc7564e5534703de3ce5652454b02bb17c823aaaabb19a6c0f9192` 확인. 물리 기기 테스트는 미실행.
- 백업/복구 검증은 임시 SQLite·임시 영상만 사용하며 원본 데이터 경로를 쓰지 않았다. 커밋된 WAL·세션 무효화·손상·참조 누락·경로 탈출·기존 대상 거부를 확인했다.
- 운영자 변경 검증은 임시 DB와 시험용 비밀 파일로 수행했다. 새 비밀번호 로그인, 이전 비밀번호·운영자 세션 거부, 일반 회원 세션 유지, dry-run·권한 검사를 통과했다. 공백을 포함한 비밀번호도 기존 로그인 API와 동일하게 정규화하며, 공백 제거 후 짧은 비밀번호는 변경 전에 거부한다.
- 마지막 보강 코드 확인: Android 보고서 경로의 심볼릭 링크 차단·파일 권한, APK 검증 실패 처리, 서버 runtime 메타데이터의 운영자 비밀 값 제외가 자동 테스트에 포함되어 통과했다. 이번 재개 작업에서는 추가 하위 에이전트 검토를 실행하지 않았다.
- 배포 설정은 소스로 검토했다. `docker compose version` 및 `config --quiet`는 Compose 플러그인 부재로 실패했고 `docker info`는 Docker 소켓 permission denied였다. Caddy 실행 파일도 없어 Caddy 설정 검증·컨테이너 빌드/기동은 미실행이다. 실제 외부 배포·인증서 발급·스토어 제출은 수행하지 않았다.
- 변경한 스크립트 구문, CLI 도움말, 문서 상대 링크, `git diff --check`와 새 변경 파일의 공백 검사를 통과했다. 실제 계정 비밀번호·앱 데이터 변경과 커밋·push는 수행하지 않았다.
