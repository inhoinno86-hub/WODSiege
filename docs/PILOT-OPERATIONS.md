# 파일럿 운영·개인정보 처리 준비서

기준일: 2026-09-06. **내부 검토 초안이며 승인된 이용약관·개인정보 처리방침·법률 검토 결과가 아니다.**

목적은 개발용 `pilot-v1`에서 실제 참가자가 있는 시험 운영으로 넘어가기 전에 결정할 내용, 담당 역할, 관찰 가능한 완료 기준을 정리하는 것이다. 사용자의 후속 작업 요청에 따라 작성했지만, 코치·Box·개인정보 책임자가 승인했다고 대신 기록하지 않는다. 실제 참가자 초대, 개인정보 수집 확대, 외부 배포, 데이터 삭제는 이번 작업으로 실행하지 않는다.

| 구분 | 현재 상태 | 다음 완료 기준 |

승인 기록 양식:

```text
결정 ID / 정책 버전:
결정 사항과 적용 시작 시각:
이전 경기에도 적용하는가? (예/아니오, 이유):
승인한 역할 / 승인 일시 / 내부 승인 기록 참조:
영향받는 코드·화면·검사:
검증 결과 / 사용자 안내 방법:
```

정책 상수는 서버 코드에 있고 경기별 정책 전체를 복사해 두지 않는다. 과거 결과 정정 시 현재 코드로 이후 경기를 재계산하므로 **새 규칙으로 상수만 교체하면 과거 점수까지 달라질 수 있다.** 운영 정책 변경에는 버전 적용 범위와 재계산 호환성 검사를 먼저 설계한다. 승인 없이 수치를 바꾸지 않는다.

## 3. 보관 정보와 접근 범위 점검

| 정보 | 현재 저장 위치·노출 범위 | 운영 전 처리 결정 |
| --- | --- | --- |
| 이름·이메일·비밀번호 검증값 | SQLite `users`; 자기 계정 응답 외 이메일·비밀번호 검증값은 회원 목록에 없음 | 필요 항목·목적·수정/탈퇴·보관 기간·본인 확인 |
| 회원 이름·소속·역할 | 현재 로그인한 사용자의 `/api/state` 회원 목록에 전체 사용자 ID/이름/소속/역할 포함 | 모든 회원에게 전체 명단을 보여 줄지, 필요한 Box/경기 범위로 최소화할지 승인·구현 검토 |
| Box 주소·중심 좌표·회원 명단·현장 확인 여부/시각 | Box 조회 응답에 포함. 원시 사용자 좌표와는 다름 | 공개 범위·확인 시각 노출 필요성·동의 내용 |

| 비공개 운동 영상·동의 시각 | `uploads/` 파일 + DB 설명표; 경기 권한·양측 제출 여부로 접근 제한 | 참가자·주변인 촬영 고지, 보관/삭제·이의 보존 예외, 저장비용 |
| 경기·선수·기록·결과·정정 이력 | DB; 공개 모집 외에는 운영자·해당 경기 참가 권한으로 제한 | 탈퇴 후 식별 정보와 경기 무결성의 처리 방법 |
| 점수·포인트 장부 | DB; 운영자 또는 자기 Box 범위 | 정정 근거·감사 기간·개인 식별 정보 최소화 |
| 로그인 세션 | DB의 해시 검증값·만료 시각, 기기의 세션 저장 공간 | 접근 취소·복구 후 재로그인·기기 분실 절차 |
| 백업·검증 보고서·서버 로그 | 백업에도 위 민감 정보가 포함될 수 있음 | 백업 암호화·접근자·보관 수명·삭제 반영·로그 최소화 |

현재 저장 방식과 API 응답에 근거한 목록이다. ‘위치·영상이 제한된다’는 이유로 **모든 개인정보가 필요한 사람에게만 최소 공개된 상태라고 주장하지 않는다.** 공개 범위 검토가 끝나기 전에는 가상 계정과 테스트 클립을 사용한다. 실제 개인정보·연락처·신분증·영상·위치 원문을 Git 문서, 이슈, 자동 테스트, 에이전트 작업 메시지에 넣지 않는다.

## 4. 개인정보 요청 처리 절차 초안

자동 삭제 기능을 운영 승인 없이 추가하거나 기존 데이터를 일괄 삭제하지 않는다. 실제 요청 처리 전 책임자·접수 채널·처리 기한·확인 수단을 정하고 관련 정책 검토를 받는다.

1. **접수:** 승인된 비공개 채널로 요청 번호, 열람/수정/삭제 유형, 대상 범위를 기록한다. 공개 저장소에는 내용 대신 요청 번호만 남긴다.
2. **신원·권한 확인:** 기존 계정 통제 여부 등 승인된 수단으로 확인한다. 확인을 명목으로 불필요한 신분증을 수집하지 않는다.
3. **영향 확인:** 진행 경기·이의·회원 소속·관리자 권한·영상·점수 이력·백업과 연결된 정보를 목록화한다.
4. **처리 결정:** 삭제/비식별화/보존 예외의 적용 범위와 근거를 책임자가 결정한다. 관리자 탈퇴는 권한 양도와 진행 경기 처리를 함께 정한다. 현재 이 업무의 앱 내 기능은 미구현이다.
5. **검증 후 적용:** 별도 복원 환경에서 참조·권한·재계산이 깨지지 않는지 확인하고, 승인된 정확한 대상만 처리한다. 증거 없는 점수를 만들거나 조정 이력을 조용히 지우지 않는다.
6. **결과 확인:** 요청자에게 처리 범위와 남는 정보·이유를 안내하고, 승인된 보존 기간 후에는 백업에도 같은 정책이 적용되도록 추적한다.

비공개 처리 기록 최소 양식: 요청 번호 / 유형 / 담당 역할 / 확인 상태 / 영향받는 내부 ID / 결정·근거 / 실행 승인 / 실행·검증 시각 / 백업 반영 계획 / 통지 상태. 실제 값은 접근 통제된 별도 시스템에 보관한다.

완료 기준: 탈퇴·진행 중 분쟁·공동 영상·관리자 계정·백업 복원 이후의 다섯 시나리오에서 처리 범위와 담당자가 명확하고, 승인된 절차를 기술적으로 검증한다. 이 문서 작성만으로 완료가 되지 않는다.

## 5. 경기 분쟁·정정 운영 절차 초안

1. 운영 목록에서 경기 ID·기한·제출 상태·이의 사유를 확인한다. 자신의 Box/출전 경기의 판정을 맡지 않는다.
2. 양측 제출 자료와 고정된 운동 버전·명단으로 비교한다. 영상의 필요한 시점을 기록하며 다른 채널에 복제·공유하지 않는다.
3. 양측 증거가 없다면 정상 승자를 강제로 만들지 않는다. 분쟁 상태 또는 검토 기한 경과 시 근거를 남겨 무효 처리할 수 있다.
4. 정상 판정에는 양측 증거와 채점 근거가 필요하다. 양측 확인이 끝난 일반 경기는 검토 기한 종료 후 관리자가 확정한다. 기한만 지나서 자동 확정되지는 않는다.
5. 확정 후 정정은 이전 결과를 보존한 채 별도 이유를 남긴다. 뒤 경기의 레이팅, 같은 상대 하루 제한, 포인트 회수와 음수 잔액도 함께 확인한다.
6. 외부 연락·응답 기한·재검토 담당자·처리 기록 보관 기간은 D-07/D-13 승인 후 채운다. 앱 내 알림이 휴대전화 푸시나 실제 사람의 연락을 대신한다고 가정하지 않는다.

완료 기준: 다른 Box의 독립 운영자 계정으로 분쟁→근거 판정→정정→후속 점수 검증을 완료하고, 당사자 계정의 자기 판정이 거부됨을 확인한다.

## 6. 장애·복구와 첫 외부 시험의 시작 조건

- 데이터 손상이 의심되면 먼저 신규 쓰기를 멈추고 담당자에게 알린다. 확인 없이 원본 DB나 영상 파일을 덮어쓰지 않는다.
- 백업·복원은 [복구 안내](BACKUP-RESTORE.md)의 새 경로 복원 방식으로 연습한다. 복원이 실제로 성공하기 전에는 ‘백업 있음’을 ‘복구 가능’으로 표시하지 않는다.
- 서버 연결·도메인·HTTPS·프록시·헬스체크는 [배포 준비 안내](DEPLOYMENT.md)대로 검증한다. 인증서·배포 계정·비용이 없는 상태에서는 공개하지 않는다.
- 첫 외부 시험의 필수 조건: Fold7 인수, D-01~D-13 승인, 개인정보 절차와 접근 범위 검토, 복원 리허설, 운영자·연락 창구 지정, 서버·영상 비용 한도와 중단 기준 승인.
- 중단 조건 후보: 비인가 영상/위치 열람, 결과·포인트 중복/손실, 백업 복구 실패, 통제되지 않는 저장 비용. 실제 운영의 수치·담당자·연락 기한은 책임자가 확정한다.

## 7. 지금 필요한 사용자·운영자 입력

1. 테스트할 실제 기기의 연결 가능 여부와 정확한 모델.
2. 첫 파일럿 지역·참가 Box·성인/미성년 범위, 규칙을 승인할 코치·운영 담당자.
3. 개인정보 책임자·요청 접수 채널·보관/삭제 정책의 검토 및 승인 담당자.
4. 서버·도메인 보유 여부, 사용할 배포 환경·허용 비용·공개 범위.

비밀번호·API 키·스토어 서명 키를 이 문서나 채팅에 적지 않는다. 필요한 값은 배포 환경의 비공개 설정으로 제공한다.
