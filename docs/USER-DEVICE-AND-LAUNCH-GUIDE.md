# WODSiege 실기기 검증 및 사용자 작업 가이드

- 작성일: 2026-09-06
- 대상: Galaxy Z Fold7과 현재 Linux 개발 PC를 사용하는 프로젝트 담당자
- 목적: 직접 수행할 기기 조작·확인·운영 결정을 순서대로 안내
- 사용법: 실제 확인한 항목만 `[x]`로 변경하고, 실패·미실행·해당 없음은 이유와 함께 기록
- 현재 확인된 상태: 자동 테스트 54개, 브라우저 E2E 8개, 웹 빌드 통과
- 현재 남은 상태: Fold7 실기기 미검증, 운영 정책 미승인, 외부 배포 미실행
- 참고: 이 문서는 수행 안내서이며 실기기 통과 기록이나 운영 승인서가 아님

## 1. 내가 할 일의 우선순위

- [ ] **먼저:** Fold7, 데이터 전송용 USB 케이블, 개발 PC 준비
- [ ] **다음:** USB 디버깅 허용 → 사전 점검 → 로컬 서버 실행 → APK 설치
- [ ] **당일 검사:** 로그인, 접기·펼치기, 키보드, GPS, 영상, 연결 실패 복구 확인
- [ ] **후속 검사:** 두 Box의 경기 생성부터 결과 확정·분쟁·정정까지 확인
- [ ] **결정할 일:** 참가 지역·Box·인원·연령·경기 규칙·개인정보 담당자 지정
- [ ] **공개 전 준비:** 서버·도메인·예산·공개 범위 결정, 백업 복구와 HTTPS·서명 APK 검증
- [ ] **전달할 일:** 검사 결과와 결정 사항을 이 문서 마지막 양식으로 정리

## 2. 검사 전 준비물과 기록

- [ ] Fold7 충전 및 화면 잠금 해제
- [ ] 충전 전용이 아닌 데이터 전송 가능한 USB 케이블 준비
- [ ] 개발 PC에서 `/home/inno/repo/WODSiege` 폴더 접근 확인
- [ ] 시험용 계정 이메일과 비밀번호 준비; 비밀번호는 앞뒤 공백을 제외한 10~200자
- [ ] 개인정보가 없는 짧은 MP4 또는 WebM 시험 영상 준비; 현재 업로드 상한 100MB
- [ ] 기기 모델명, Android 버전, One UI 버전, Android System WebView 버전 기록
- [ ] 검사 날짜, 앱 버전, APK SHA-256 기록
- [ ] 원시 GPS 좌표·실명·비밀번호·토큰·개인 영상은 공개 검사 기록에 넣지 않기
- [ ] 실제 위치 확인은 본인이 동의한 장소에서 수행; 좌표는 서버에 보관됨을 확인

## 3. USB 연결과 사전 점검

### 3-1. 휴대전화에서 할 일

- [ ] 설정에서 개발자 옵션을 활성화하고 USB 디버깅 켜기
- [ ] PC와 USB 연결 후 휴대전화 잠금 해제
- [ ] 연결한 본인 PC에 대한 USB 디버깅 허용 창 확인
- [ ] 허용 창이 없거나 기기가 안 보이면 케이블·USB 포트·연결 모드 확인

### 3-2. PC에서 할 일

- 저장소 루트에서 아래 명령 실행:

```bash
cd /home/inno/repo/WODSiege
export PATH="$PWD/.tools/android-sdk/platform-tools:$PATH"
adb devices -l
npm run android:preflight
```

- [ ] `adb devices -l`에서 사용할 기기가 `device` 상태인지 확인
- [ ] 사전 점검 결과가 `READY_FOR_MANUAL_ACCEPTANCE`, 종료 코드 `0`인지 확인
- [ ] 이 결과는 수동 검사 시작 가능 상태임을 확인; 설치·GPS·접힘 검증 통과를 뜻하지 않음
- 기기가 여러 대이면 아래처럼 명시적으로 선택하고 이후 모든 adb 명령에도 `-s "$WODSIEGE_DEVICE_SERIAL"` 적용:

```bash
read -r -p '검사할 기기 시리얼: ' WODSIEGE_DEVICE_SERIAL
node scripts/android-preflight.mjs --serial "$WODSIEGE_DEVICE_SERIAL"
adb -s "$WODSIEGE_DEVICE_SERIAL" reverse tcp:8787 tcp:8787
```

- 사전 점검 기록이 필요하면 새로운 파일명으로 저장:

```bash
node scripts/android-preflight.mjs --output artifacts/fold7-preflight-20260906-01.json
```

- 기존 보고서는 덮어쓸 수 없으므로 다음 검사는 `-02` 등 새 이름 사용
- 명시한 시리얼은 보고서에 남으므로 외부 공유 전 제거
- APK가 없거나 앱 소스를 변경한 경우 아래 명령으로 다시 빌드:

```bash
npm run android:build
```

- 의존성·JDK·SDK가 없는 새 PC는 [Android 개발 환경 안내](ANDROID-TESTING.md)의 설치 절차부터 수행

## 4. 로컬 서버 실행과 APK 설치

### 4-1. 터미널 A: 시험용 서버 실행

- [ ] 기존 서버가 8787 포트를 사용 중인지 확인; 기존 서버가 있다면 해당 터미널에서 정상 종료 후 진행
- [ ] 아래 데이터 경로는 첫 검사에 사용할 새 경로로 지정; 기존 데이터 삭제·덮어쓰기 금지
- [ ] 같은 검사를 재개할 때는 동일 경로 사용; 매번 새 경로를 쓰면 이전 계정·경기가 보이지 않음
- [ ] 시험용 운영자 이메일과 비밀번호 입력; 이메일은 앱에서 만들 일반 회원 계정과 다르게 지정
- [ ] 서버가 실행되는 동안 이 터미널 유지

```bash
cd /home/inno/repo/WODSiege
export NODE_ENV=development
export HOST=127.0.0.1
export PORT=8787
export WODSIEGE_DATA_DIR="$PWD/data/fold7-manual-20260906-01"
read -r -p '시험용 운영자 이메일: ' WODSIEGE_OPERATOR_EMAIL
read -r -s -p '시험용 운영자 비밀번호 (10~200자): ' WODSIEGE_OPERATOR_PASSWORD
export WODSIEGE_OPERATOR_EMAIL WODSIEGE_OPERATOR_PASSWORD
npm run server
```

- 운영자는 Box 운영권 승인과 독립 분쟁 판정에 사용; 선수나 Box 관리자로 사용하지 않기
- 동일 운영자가 이미 있으면 입력한 새 비밀번호로 변경되지 않음; 변경이 필요하면 [운영자 비밀번호 안내](OPERATOR-PASSWORD.md) 참조
- 기존 셸에 `WODSIEGE_OPERATOR_EMAIL_FILE` 또는 `WODSIEGE_OPERATOR_PASSWORD_FILE`이 설정되어 있으면 직접 입력 방식과 충돌할 수 있음; 시험용 새 터미널에서 불필요한 파일 설정을 해제하고 진행
- 이 시험 서버는 PC 내부에서 실행하며 외부 인터넷에 공개하지 않음

### 4-2. 터미널 B: 서버 확인·포트 연결·설치

- 아래 명령은 연결된 기기가 한 대일 때의 예시:

```bash
cd /home/inno/repo/WODSiege
export PATH="$PWD/.tools/android-sdk/platform-tools:$PATH"
curl --fail --silent --show-error http://127.0.0.1:8787/api/health
adb reverse tcp:8787 tcp:8787
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n app.wodsiege.pilot/.MainActivity
```

- [ ] health 응답 `{"ok":true,"mode":"pilot"}` 확인
- [ ] APK 설치 결과 `Success` 확인
- [ ] WODSiege 시작 화면 확인
- [ ] 앱의 **서버 연결 설정**에서 `http://localhost:8787` 입력·저장
- [ ] 일반 회원 가입·로그인과 화면 조회 확인
- PC에서 `localhost`는 PC, 앱에서 `localhost`는 휴대전화 주소; `adb reverse`가 두 포트를 연결함
- 현재 debug APK는 loopback HTTP만 허용하므로 `http://192.168...` 등 LAN 주소로 임의 변경하지 않기
- USB 연결이나 PC 서버가 끊기면 앱의 API 요청도 실패함
- 앱 설치 중 서명 충돌이 발생하면 기존 설치본·서명부터 확인; 데이터가 지워지는 앱 삭제로 바로 해결하지 않기

## 5. 실기기 수동 체크리스트

### 5-1. 화면과 접기·펼치기

- [ ] 접힌 커버 화면에서 주요 메뉴·버튼·목록 확인
- [ ] 펼친 메인 화면에서 목록과 상세 영역 확인
- [ ] 경기 생성 화면에 값을 입력한 상태로 접기·펼치기 반복
- [ ] 회전, 분할 화면, 키보드 표시 상태에서 핵심 버튼 접근 확인
- [ ] 시스템 글꼴을 크게 설정한 뒤 글자·버튼 겹침 확인; 검사 후 원래 설정 복원
- [ ] 상태 표시줄·하단 내비게이션 영역이 입력창이나 버튼을 가리지 않는지 확인
- 통과 기준: 화면 잘림 없이 핵심 조작 가능, 작성 중 입력·선택 유지

### 5-2. GPS와 권한

- [ ] 시험용 Box를 등록하고 본인의 소속 상태 확인
- [ ] 위치 동의 체크 후 **현재 위치로 참여 확인** 실행
- [ ] 정밀 위치 허용 시 실제 Box 근처에서 확인 성공 여부 검사
- [ ] 대략적 위치 허용 시 결과와 오류 안내 검사; 정확도가 부족하면 거부되는 것이 정상
- [ ] 위치 권한 거절, 반복 거절 후 설정에서 재허용하는 경로 검사
- [ ] 기기 위치 기능 꺼짐·실내 수신 불량 상태의 안내와 재시도 검사
- [ ] Box 밖에서 확인 시 성공으로 잘못 표시되지 않는지 검사
- 통과 기준: 유효 위치에서 확인 성공, 거절·오차·수신 실패 시 이유와 복구 안내 표시
- 현재 개발 기준: Box 반경 150m 이내, 정확도 100m 이내, 최근 10분 위치
- 확인 성공 후에는 같은 계정의 재확인이 제한되므로 실패 조건은 성공 전에 검사하거나 다른 시험 계정 사용
- GPS는 실사용자·운영권 확인을 대신하지 않으며 운영자의 수동 출석 승인 기능은 없음

### 5-3. 영상과 연결 복구

- [ ] 아래 6절의 경기 준비 후 Android 파일 선택기에서 시험용 MP4/WebM 선택
- [ ] 업로드 진행 표시·완료·기록 제출 확인
- [ ] 양측 제출 전 상대 영상이 노출되지 않는지 확인
- [ ] 양측 제출 후 상대 계정으로 로그인하여 권한에 맞게 영상 재생 확인
- [ ] 업로드 중 홈 화면 전환·화면 잠금 후 돌아와 실제 전송 상태 확인
- [ ] 업로드 중 USB를 분리하여 API 연결 단절 후 오류·재시도 확인
- [ ] USB 재연결 후 `adb reverse tcp:8787 tcp:8787` 재실행하고 복구 확인
- [ ] 제출 요청 재시도 후 기록이 중복 생성되지 않는지 확인
- 통과 기준: 실패한 전송을 성공으로 표시하지 않음, 권한 있는 계정만 재생 가능, 재시도로 정상 복구
- 현재 제한: 백그라운드 전송 보장·청크 이어올리기 없음; 처음부터 다시 업로드할 수 있음
- USB reverse 사용 중 Wi-Fi만 끄는 것으로는 API 단절 검사가 되지 않을 수 있음

### 5-4. 앱 수명주기

- [ ] Android 뒤로가기와 화면 복귀 확인
- [ ] 앱을 백그라운드로 보낸 뒤 복귀 확인
- [ ] 앱 프로세스 종료 후 다시 실행하여 로그인·작성 초안 상태 확인
- [ ] PC 서버 정상 종료 후 앱의 연결 오류 표시 확인
- [ ] 동일 데이터 경로로 서버를 다시 시작한 뒤 기존 계정·경기 조회 확인
- 통과 기준: 오류 안내와 재로그인·재시도 경로 제공, 서버에 저장한 계정·경기 유지
- 현재 제한: 세션은 24시간이며 앱 프로세스 종료 후 재로그인이 필요할 수 있음; 자동 로그인 유지가 필수 통과 기준은 아님

## 6. 경기 전체 흐름 검사

### 6-1. 계정과 Box 준비

- [ ] 서로 다른 시험용 운동자 계정 6개 준비; Box A/B에 각각 3개 배정
- [ ] 각 Box의 첫 계정이 Box 등록 후 나머지 2명의 가입 신청 승인
- [ ] 각 계정이 해당 Box 소속과 위치 이용에 동의하고 현장 확인
- [ ] 별도 운영자 계정이 개발 검사임을 명시한 근거로 두 Box 운영권 승인
- [ ] 두 Box가 구성원·위치·운영권 요건을 모두 충족했는지 확인
- 기술 검사에서는 계정을 바꿔 사용할 수 있으나 같은 폰의 다중 계정 성공은 서로 다른 실사용자 확인의 증거가 아님
- GPS 성공 검사에는 실제 기기 위치가 필요; 자동 테스트용 좌표 주입 결과로 대체하지 않기

### 6-2. 경기 진행

- [ ] 개인전·한 장소 경기 생성; 준비를 마칠 수 있는 미래 일시 지정
- [ ] 상대 관리자 도전 신청 → 방어 관리자 수락
- [ ] 양측 출전 명단과 조건 동의 → 조건 잠금 확인
- [ ] 잠금 후 한쪽이 조건·명단을 임의 변경할 수 없는지 확인
- [ ] 예정 시각 이후 경기 시작
- [ ] 양측 시험 영상·선수별 기록 제출 후 상대 기록 검토
- [ ] 예정 시각부터 48시간 경과 후 일반 경기 확정 및 순위·원장·포인트 확인
- [ ] 별도 경기에서 이의 제기 → 독립 운영자 근거 판정 → 확정 결과 무효 정정 확인
- [ ] 3인 팀전·각 Box 진행 방식으로도 전체 과정 반복
- [ ] 시작 전 취소, 제출·검토 기한 경과 시 안내와 운영 처리 경로 확인
- 통과 기준: 합의한 명단·기록대로 상태 진행, 분쟁 중 보상 보류, 확정·정정 내역과 점수 일치, 중복 반영 없음

### 6-3. 일정상 주의할 점

- 제출 마감: **경기 예정 시각 +24시간**
- 검토 마감: **경기 예정 시각 +48시간**
- 양측 검토를 일찍 마쳐도 일반 확정은 검토 마감 이후에 가능
- 마감이 지나도 자동 확정되지 않으므로 화면에서 확정 처리 필요
- 일반 경기 확정 검사는 최소 이틀에 걸쳐 재접속 일정 확보
- 분쟁 판정 경로만 당일 확인했으면 일반 확정은 별도 미실행으로 기록
- PC·휴대전화 시계를 변경하거나 DB를 편집하여 기한을 우회하지 않기
- 빠른 전체 흐름 회귀 검사는 개발 PC의 `npm test`, `npm run test:e2e` 사용; 실기기 검사 결과와 구분

## 7. 문제가 생겼을 때

| 증상 | 직접 확인할 내용 | 해결되지 않을 때 전달할 정보 |
| --- | --- | --- |
| `BLOCKED_NO_DEVICE` | USB 케이블·포트·잠금 해제·디버깅 설정 | PC OS, 기기 모델, 상태 문자열 |
| `BLOCKED_UNAUTHORIZED` | 휴대전화의 USB 디버깅 허용 창 | 허용 창 표시 여부 |
| `BLOCKED_DEVICE_PERMISSION` | Linux USB 장치 접근 권한 | 권한 오류 문구; 임의로 전체 공개 권한 부여 금지 |
| `BLOCKED_MULTIPLE_DEVICES` | 대상 시리얼을 명시해 재실행 | 선택 이후 결과; 공개 기록에는 시리얼 제외 |
| `BLOCKED_LOCAL_APK_UNAVAILABLE` | APK 존재·빌드 성공·검증 도구 상태 | 빌드 또는 사전 점검 오류 |
| 앱 서버 연결 실패 | PC health, 앱 주소, USB 연결, reverse 매핑 | 실패한 단계와 오류 문구 |
| GPS 확인 실패 | 소속·동의·권한·위치 기능·Box와의 거리·정확도 | 권한 종류·실내/실외·오류; 좌표 원문 제외 |
| 영상 재생 실패 | MP4/WebM 형식·용량·양측 제출·접근 권한 | 파일 형식·크기·증상; 개인 영상 전달 금지 |
| 경기 시작·확정 버튼 비활성 | 양측 합의, 예정 시각, 제출·검토 마감 | 경기 상태·예정 시각·표시된 마감 |
| 앱 종료 후 로그아웃 | 다시 로그인하여 서버 데이터 조회 | 재로그인 결과, 저장 데이터 누락 여부 |
