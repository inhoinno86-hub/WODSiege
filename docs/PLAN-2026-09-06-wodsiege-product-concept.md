## 1. 문서 목적과 읽는 방법

이 문서는 WODSiege가 누구를 위해 어떤 경험을 제공하고, 어떤 규칙으로 운영되어야 하는지 정의한다. 추후 개발 작업 지시서에서 **작업 목표·방향·내용·완료 기준**을 작성할 때 공통 기준으로 활용한다. 현재 문서는 기능 구현 지시서나 승인된 운영 규정이 아니다.

요구사항은 다음 세 종류로 구분한다.

| 구분 | 의미 |
| --- | --- |
| 원안 | 사용자가 직접 제시한 방향. 제품 개념의 출발점으로 유지한다. |
| 권고안 | 원안을 구체화하기 위한 이번 문서의 제안. 사용자 승인 전에는 확정 정책으로 취급하지 않는다. |
| 결정 필요 | 개발 범위나 서비스 운영에 영향을 주므로 후속 기획에서 선택해야 하는 항목. |

별도 표시가 없는 상세 정책은 모두 권고안이다. 숫자와 산식 예시는 설계 이해를 위한 가정이며 확정 운영값이 아니다. 외부 시장 조사, 공식 경기 규정 대조, 법률 검토는 이번 문서의 범위에 포함하지 않았다.

## 2. 서비스 정의

### 2.1 한 문장 소개

**WODSiege는 CrossFit 운동자가 소속 Box를 대표해 같은 WOD 기록으로 개인전·단체전을 겨루고, 다른 Box의 도장을 깨거나 자신의 도장을 지키며 성장하는 경쟁 커뮤니티 앱이다.**

WOD는 해당 경기에서 수행할 운동 구성과 기록 기준을 뜻한다. Box는 운동자가 소속되는 체육관 단위의 커뮤니티이자 대결의 주체다. Siege는 다른 Box에 도전하는 경험을 표현한다.

### 2.2 원안에서 유지할 핵심

- CrossFit 운동자를 주 대상으로 하며, 운동 동기와 지속적인 참여를 높이는 것이 목적이다.
- 같은 WOD의 수행 기록을 비교하는 대결을 중심에 둔다.
- 최소 3명 이상이 동일 위치에서 GPS를 통해 참여를 확인하고 Box를 등록한다.
- 개인전과 단체전을 지원한다. 단체전의 인원 및 남녀 구성은 추후 결정한다.
- 도전을 받는 Box가 WOD를 제안하고, 도전 Box가 내용을 보고 참가 여부를 결정한다.
- 경기 일시와 장소를 정한다. 한 Box에 모이거나 각자의 Box에서 진행할 수 있다.
- 경기 영상과 카운팅 기록을 남긴다.
- 도장 지키기·깨기의 결과로 Box 점수가 증가하거나 감소한다.
- 동네·지역구·전국·세계 단위로 순위를 제공한다.
- 포인트를 Box 홍보 등 앱 내 활동에 활용할 수 있도록 한다.

### 2.3 제품이 제공해야 할 가치

| 사용자 | 기대하는 경험 | 제품이 제공할 가치 |
| --- | --- | --- |
| 운동자 | 기록을 남기는 것에서 나아가 도전할 상대와 목표를 찾음 | 비슷한 수준의 상대, 대결 이력, 개인 성장 확인 |
| Box 운영자·코치 | 회원이 함께 준비하고 참여하는 이벤트를 운영함 | 대표 선수 구성, 친선 교류, 지역 내 Box 소개 |
| Box 구성원 | 직접 출전하지 않아도 소속 Box의 경기에 참여함 | 응원, 경기 결과 공유, 공동 성취감 |

제품의 성공은 경기 수와 순위 경쟁만으로 판단하지 않는다. 첫 도전을 마친 운동자와 Box가 공정한 경험을 했다고 느끼고 다시 참여하는지를 함께 확인한다.

## 3. 제품 원칙과 핵심 용어

### 3.1 제품 원칙

1. **비교 가능한 기록:** 같은 WOD 버전·부문·팀 구성·채점 방식일 때 공식 승패를 결정한다.
2. **결과의 신뢰:** 자기 입력 기록만으로 순위를 확정하지 않고, 영상과 판정 근거를 연결한다.
3. **반복 가능한 도전:** 도전→준비→경기→결과→재도전의 흐름을 쉽게 만든다.
4. **참여 기회의 균형:** 인원이 많은 Box가 단순 경기 횟수만으로 순위를 독점하지 않도록 한다.
5. **운동 수준의 존중:** 초보자도 자신의 수준에서 참여할 수 있도록 부문을 분리한다.
6. **평판과 사용 잔액의 분리:** 홍보에 포인트를 사용해도 경기 실력 순위가 내려가지 않게 한다.

### 3.2 용어

| 용어 | 정의 |
| --- | --- |
| 방어 Box | 자신의 도장에 도전장을 열고 WOD를 제안한 Box |
| 도전 Box | 공개된 WOD와 조건을 보고 도전을 신청한 Box |
| 도장 | Box의 도전·방어 이력과 성취를 표현하는 서비스 개념 |
| 도전장 | WOD, 참가 조건, 일시·장소 등을 담은 경기 모집 제안 |
| 경기 | 양측이 조건에 합의하고 진행하는 하나의 대결 |
| 부문 | 운동 수준, 참가 구분, 개인·팀 구성 등 기록을 비교할 범위 |
| 공식전 | 등록·참가·검증 요건을 충족하고 순위에 반영되는 경기 |
| 친선전 | 순위 반영 없이 교류와 연습을 목적으로 진행하는 경기 |
| 레이팅 | 해당 부문에서 Box의 경쟁 수준을 나타내는 순위 점수 |
| 활동 포인트 | 홍보나 꾸미기 등에 사용하는 별도의 적립·소비 잔액 |

도장을 깬다는 것은 해당 경기에서 방어 Box를 이겼다는 뜻이다. Box 소유권, 운영 권한, 다른 회원의 소속은 바뀌지 않는다. 지도상의 지역 점령도 초기 개념에 포함하지 않는다.

## 4. 사용자와 Box 등록

### 4.1 역할과 권한

| 역할 | 주요 권한 |
| --- | --- |
| 운동자 | 가입, Box 소속 신청, 경기 참가, 기록·영상 제출, 자신의 결과 확인 |
| Box 관리자 | Box 정보 관리, 구성원 승인, 도전장 게시·수락, 출전 명단 확정 |
| 카운터·심판 | 배정된 경기의 반복 횟수·시간·무효 동작과 근거 기록 |
| 서비스 운영자 | Box 중복·사칭 검토, 분쟁 판정, 제재, 확정 결과 정정 |

한 사람이 운동자와 Box 관리자 역할을 함께 가질 수 있다. 자신의 경기의 최종 분쟁 판정은 맡을 수 없도록 한다. MVP의 심판은 별도 자격 인증 체계 없이 양측이 합의한 사람으로 시작할 수 있으며, 이 경우 독립성의 한계를 표시한다.

### 4.2 Box 등록 흐름

1. 대표 신청자가 이름, 주소, 지도 위치, 소개를 입력한다.
2. 시스템이 같은 이름·주소·근접 좌표의 기존 Box 후보를 보여준다.
3. 대표 신청자를 포함한 서로 다른 사용자 최소 3명이 해당 위치에서 GPS 참여 확인을 완료한다.
4. 각 참여자가 해당 Box 소속에 동의한다.
5. 등록 요건과 중복 여부를 확인한 뒤 Box를 활성화한다.
6. 실제 체육관 운영 권한은 별도의 운영자 확인 절차로 표시한다.

‘동일 위치’는 좌표값의 완전 일치가 아니라 등록 지점 주변의 허용 반경과 확인 시간 범위로 정의한다. 허용 반경, GPS 정확도, 3명의 동시 방문 필요 여부는 결정해야 한다. 위치 권한 거부나 실내 수신 오류에는 재시도·운영자 검토 경로를 제공한다.

GPS 확인은 같은 장소에 있었다는 근거일 뿐, 체육관 운영 권한이나 서로 다른 실사용자임을 완전히 증명하지는 않는다. **구성원·위치 확인**과 **체육관 운영자 확인**을 서로 다른 상태로 관리한다. 공식전 개설은 운영 권한까지 확인된 Box에 허용하는 방안을 권고한다.

### 4.3 소속 및 중복 정책

- 공식전용 주 소속 Box는 한 번에 하나로 제한하는 안을 권고한다.
- 같은 건물에 여러 체육관이 있을 수 있으므로 근접 좌표만으로 등록을 차단하지 않는다.
- 이미 등록된 Box라면 새로 만들기보다 가입 또는 관리 권한 요청을 안내한다.
- 경기 명단 확정 당시의 소속을 결과에 보존한다. 이후 이적해도 과거 경기의 소속이나 점수를 이동하지 않는다.
- Box 구성원이 3명 미만으로 줄면 이력은 유지하되 신규 공식전 개설을 제한하는 안을 권고한다. 진행 중 경기의 처리 정책은 별도 결정한다.
- 공식 순위의 지역은 Box의 확인된 주소를 기준으로 한다. 사용자의 현재 GPS 이동에 따라 바뀌지 않는다.

## 5. 개인전·단체전과 도장깨기

### 5.1 경기 유형

| 유형 | 대결 단위 | 초기 적용안 |
| --- | --- | --- |
| 개인전 | 방어 Box 대표 1명 대 도전 Box 대표 1명 | 개인 기록을 저장하고 해당 개인전 부문의 Box 레이팅에 반영 |
| 단체전 | 양 Box에서 동일 규칙으로 구성한 팀 | 고정 인원·고정 구성의 한 가지 형식부터 도입 |
| 친선전 | 개인 또는 팀 | 공식전 운영이 안정된 다음 확장, 순위 변동 없음 |

개인전도 Box를 대표하는 도장 대결로 정의한다. Box에 속하지 않은 사용자 간 자유 개인 매칭과 독립적인 개인 레이팅은 후속 기능으로 둔다. 개인의 경기 이력과 WOD 기록은 초기부터 보존한다.

단체전은 남자 n명, 여자 m명, 남자 a명+여자 b명 등의 템플릿으로 확장할 수 있도록 개념을 설계한다. 초기에는 총 3명인 한 가지 팀 구성을 후보로 삼되, 실제 구성은 참여 Box와 합의해 정한다. 등록 최소 인원 3명과 경기 팀 정원은 별개 규칙이다.

팀 채점은 두 가지를 구분한다.

- **개별 수행 합산형:** 각 선수가 동일 WOD를 수행한 뒤 사전에 정한 합산 방식으로 팀 점수를 계산한다. 초기 권고 방식이다.
- **협동 수행형:** 릴레이나 공동 반복 수행 등 하나의 WOD를 팀으로 완수한다. 별도 판정 규칙이 필요하므로 후속 확장한다.

운동 수준은 예를 들어 Rx(정해진 기준 수행)와 Scaled(조정 기준 수행)로 구분할 수 있다. 명칭만 같다고 같은 부문이 되는 것은 아니며, 실제 무게·동작·횟수·채점 기준이 일치해야 한다. 성별·연령 등의 참가 구분과 확인 방식은 별도 결정한다.

### 5.2 도장깨기 흐름

1. 방어 Box가 WOD와 경기 조건을 담은 도전장을 공개한다.
2. 도전 Box가 WOD, 부문, 상대 정보, 일정, 장소를 보고 도전한다.
3. 방어 Box가 수락하고 양측이 일정·장소·명단·판정 기준을 확정한다.
4. 합의된 경기 조건을 잠근 뒤 준비 기간을 갖는다.
5. 같은 장소 또는 각자의 Box에서 WOD를 수행하고 영상·카운팅 기록을 제출한다.
6. 양측이 결과를 검토하고, 이견이 있으면 운영자가 근거를 심사한다.
7. 결과가 확정되면 도장 이력, 레이팅, 활동 포인트와 순위를 갱신한다.
8. 재도전하거나 다른 Box의 도전장을 탐색한다.

도전 Box 승리는 ‘도장 깨기 성공’, 방어 Box 승리는 ‘도장 지키기 성공’으로 표시한다. 무승부는 소유권 변화 없이 무승부 이력을 남기며, 성공 배지를 주지 않는 안을 권고한다. 무승부와 무효 경기는 구분한다.

### 5.3 방어 Box의 WOD 제안권과 공정성

방어 Box가 WOD를 제안하는 것은 서비스의 정체성으로 유지한다. 단, 임의 WOD만으로 전체 운동 능력을 대표한다고 해석하지 않으며, 순위는 WODSiege의 승인된 대결 규칙 내 성과를 뜻한다.

- WOD와 판정 기준은 도전 수락 전에 모두 공개한다.
- 양측 합의 후 일방적인 조건 변경을 막는다. 변경이 필요하면 기존 합의를 해제하고 다시 동의를 받는다.
- 초기 공식전은 검토된 템플릿 중 선택하게 해 과도한 조건 편차와 판정 부담을 줄인다.
- 자유 WOD 작성은 후속 확장한다. 공식전 반영에는 별도 검토가 필요하다.
- 장비와 수행 환경이 맞지 않으면 합의 전에 도전을 철회할 수 있다.
- 도전 거절만으로 레이팅을 차감하지 않는다. 거절·취소와 실제 패배는 다르게 처리한다.
- 반복적인 유리한 상대 선택은 향후 대진 추천·반복 상대 제한·활동 상태 표시로 보완한다.

## 6. WOD와 경기 조건

### 6.1 도전장에 필요한 정보

| 영역 | 필수 정의 |
| --- | --- |
| WOD | 이름, 버전, 동작 순서, 라운드, 반복 횟수, 무게·단위, 장비 |
| 수행 기준 | 유효 동작, 무효 동작, 시작·종료 조건, 허용 대체 동작 |
| 기록 방식 | 완료 시간, 총 반복 수, 중량 등 주 지표와 승패 비교 방향 |
| 예외 채점 | 제한 시간 미완료, 동점, 중도 포기, 실격, 미제출 처리 |
| 참가 조건 | 개인·팀, 팀 정원·구성, 운동 수준, 명단, 교체 허용 조건 |
| 경기 운영 | 일시·시간대, 개최 방식, 장소, 수행 가능 시간, 제출 마감 |
| 검증 | 카운터, 촬영 기준, 영상 공개 범위, 검토·이의 제기 기한 |

WOD 버전은 경기 결과와 함께 고정해서 보존한다. 이후 템플릿이 바뀌어도 과거 기록의 수행 조건은 바뀌지 않는다.

### 6.2 점수 방식 권고

| WOD 유형 | 기록 비교 | 정의해야 할 예외 |
| --- | --- | --- |
| For Time | 같은 과제를 완료한 시간, 짧을수록 우위 | 제한 시간 내 미완료자는 완료자 다음으로 두고 완료 반복 수 등으로 비교 |
| AMRAP | 정해진 시간 내 총 유효 반복 수, 많을수록 우위 | 라운드를 반복 수로 환산하는 기준과 동점 처리 |
| 중량 기반 | 인정된 수행 중량, 클수록 우위 | 시도 횟수, 단위, 유효 수행, 동점 처리 |

이는 앱의 채점 구조 제안이며 특정 대회의 공식 규정 인용이 아니다. 초기에는 For Time과 AMRAP부터 지원하고, 중량 기반은 후속으로 둔다.

단체전에서는 WOD마다 합산 방식을 고정한다. AMRAP은 총 유효 반복 수 합산을 후보로 삼는다. For Time은 전원 완료 시 시간 합산을 후보로 삼되, 미완료자가 있으면 단순 시간 합산이 성립하지 않으므로 미완료 인원·완료 반복 수 등 별도 순서를 결정해야 한다. 정해지지 않은 채점 조합은 공식전으로 개설하지 않는다.

### 6.3 장소와 일정

| 방식 | 경험 | 필요한 조건 |
| --- | --- | --- |
| 한 장소에 모임 | 방어 또는 도전 Box에서 직접 경기 | 수용 인원, 장비, 방문 가능 여부, 촬영·판정 동선 합의 |
| 각자의 Box | 각 Box에서 수행 후 기록 비교 | 동일 장비·WOD 조건, 수행 시간 범위, 영상·타이머 기준 통일 |

각 Box 경기의 초기 권고안은 양측이 합의한 같은 시간대의 수행 구간 내에 진행하고, 양측 제출 완료 또는 제출 마감 전에는 상대의 상세 기록을 공개하지 않는 것이다. 한 번의 지정 시도만 인정할지, 기간 내 최고 기록을 인정할지는 사전에 결정한다. 초기 공식전은 지정 시도 1회를 권고한다.

사용자에게는 현지 시간과 시간대를 명확히 보여주며, 경기 기준 시각은 하나로 저장한다. 글로벌 순위보다 먼저 국가별 주소·지역 체계와 시간대 처리 방식을 정의해야 한다.

## 7. 영상·카운팅·판정

### 7.1 기록의 구성

하나의 경기 기록은 **선수·소속·WOD 버전·원시 기록·판정 기록·증빙 영상·최종 결과**를 연결한다.

카운팅은 단순 총횟수 입력에 그치지 않고 유효 반복 수, 무효 반복 수, 구간 시간, 판정 메모를 남기는 행위로 정의한다. 논쟁이 있는 구간에는 영상 시점을 연결할 수 있도록 한다.

초기 카운팅은 사람이 수행한다. AI 자동 카운팅과 동작 판정은 후속 검증 과제로 두며, 핵심 기록 확정이 AI 성능에 의존하지 않게 한다.

### 7.2 검증 흐름

1. 경기 전 참가자, 장비, 타이머, 촬영 구도를 확인한다.
2. 경기 전체를 확인할 수 있는 연속 영상을 촬영한다.
3. 카운터가 기록과 필요한 판정 근거를 입력한다.
4. 영상 업로드와 기록 제출을 완료하면 시스템이 필수 항목·형식·기한을 확인한다.
5. 상대 Box가 규정 준수와 기록을 검토한다.
6. 양측 확인 및 이의 제기 기간 종료 후 결과를 확정한다. 기한 내 응답이 없으면 운영자 검토 대상으로 보내는 안을 권고한다.
7. 이의가 있으면 해당 경기의 점수 반영을 보류하고 운영자가 판정한다.

연속 영상과 GPS만으로 부정을 완전히 막을 수는 없다. 경기 식별 코드, 장비 확인 장면, 재사용 영상 탐지, 반복 상대 패턴 검토 등은 운영 규모에 맞춰 보완한다.

### 7.3 예외 처리

| 상황 | 권고 처리 |
| --- | --- |
| 업로드 실패 | 제출 진행 상태와 재시도를 제공하고, 수행 시각과 업로드 시각을 구분 |
| 일부 동작이 보이지 않음 | 보완 근거 검토 또는 해당 기록 인정 불가. 자동 패배로 즉시 확정하지 않음 |
| 무효 동작 이견 | 영상 시점과 이의 사유를 접수하고 판정 완료 전 결과 보류 |
| 정해진 시간 미완료 | 합의된 WOD 미완료 채점 규칙 적용 |
| 부상·중도 포기 | 중단 사유를 기록하고 사전에 합의한 기권·무효 규칙 적용 |
| 노쇼·미제출 | 일반 경기 패배와 구분해 운영 판단. 신뢰도 제재 및 몰수패 적용 여부는 정책 결정 |
| 부정행위 확인 | 결과 무효 또는 정정, 관련 점수 조정, 이의 제기 가능한 제재 |

확정 후 결과를 정정할 때는 원본과 판정 이력을 보존한다. 해당 경기만 수정하면 이후 레이팅과 불일치할 수 있으므로 재계산 또는 조정 내역 처리 방식을 정해야 한다.

### 7.4 영상 공개와 보관

영상 검증용 열람 권한과 공개 홍보용 노출 권한을 구분한다. 초기에는 참가자·양측 관리자·배정 심판·서비스 운영자 등 필요한 사람에게 접근을 제한하고, 공개 하이라이트는 별도 동의를 받는 안을 권고한다.

개발 전에 영상 보관 기간, 업로드 용량·길이, 삭제 요청, 분쟁 중 증거 보존, 등장인물의 촬영 동의 처리 방식을 결정한다. 지속적인 위치 추적은 초기 기능에 포함하지 않으며, 등록·경기 확인에 필요한 위치 정보만 다루도록 설계한다.

## 8. 레이팅·등급·순위

### 8.1 레이팅과 활동 포인트의 분리

| 구분 | 레이팅 | 활동 포인트 |
| --- | --- | --- |
| 목적 | 대결 성과와 상대 수준을 반영하는 순위 | Box 홍보와 앱 내 참여 혜택 |
| 획득·변동 | 확정 경기 결과로 증감 | 검증된 경기 완료, 도전·방어 성취 등으로 적립 |
| 패배 시 | 산식에 따라 하락 | 이미 보유한 잔액은 일반 패배로 차감하지 않는 안 |
| 사용 | 소비 불가 | 정해진 사용처에서 소비 |
| 구매·양도 | 구매·양도 불가 | 초기에는 구매·양도·현금 교환 기능 제외 |

원안의 ‘도장 지키기·깨기에 따른 획득·차감’은 레이팅으로 구현하고, ‘포인트 사용’은 활동 포인트로 구현하는 권고안이다. 하나의 잔액을 두 용도로 사용하면 홍보 지출이 경기 순위를 낮추거나, 구매력이 순위를 바꾸는 문제가 생긴다.

### 8.2 레이팅 계산 방향

- 승자는 상승하고 패자는 하락하며, 상대와의 실력 차이를 반영하는 Elo 계열 방식을 후보로 검토한다.
- 방어·도전 여부만으로 추가 레이팅을 주지 않는다. 역할별 성취는 배지나 활동 포인트로 표현한다.
- 동일한 상대와의 반복 경기에는 레이팅 반영 횟수 제한 또는 감소 규칙을 둔다. 구체적인 기간·횟수는 결정한다.
- 신규 Box는 일정 경기 수까지 임시 등급으로 표시하고 정식 순위 편입 기준을 둔다.
- 경기 종류와 팀 구성·운동 수준이 다른 결과는 초기에는 별도 순위로 관리한다. 여러 부문의 합산 종합 순위는 후속 설계한다.
- 참가 인원 수나 활동 포인트 총량을 레이팅에 직접 더하지 않는다.

예시로 양 Box가 각각 1,000점이고 변동 계수 K=24인 기본 Elo를 적용하면, 같은 레이팅의 상대에게 이긴 Box는 1,012점, 진 Box는 988점이 된다. 이는 산식 설명용 예시이며 초기 점수·계수·무승부·신규 보정 정책을 확정한 것이 아니다. 무승부도 상대 수준에 따라 점수가 변할 수 있으므로 실제 산식과 사용자 안내가 일치해야 한다.

### 8.3 지역 순위와 등급

순위는 ‘지역 범위 + 부문 + 시즌 또는 집계 기간’으로 조회한다. 같은 부문에서 같은 레이팅을 지역별로 필터링해 보여주며, 동네·전국 점수를 각각 별도로 적립하지 않는다.

- 원안의 확장 목표는 동네 → 지역구 → 전국 → 세계 순위다.
- 초기 운영 지역은 한국의 한 도시 또는 한 권역을 후보로 삼고, 동네·지역구 순위를 먼저 검증한다.
- 동네가 행정동인지 거리 반경인지, 지역구가 시·군·구인지 구체적으로 결정한다.
- 전국·세계 화면은 실제 참여 지역과 운영 체계가 확보된 후 확장한다.
- 동점은 공동 순위를 기본 후보로 삼고, 표시 정렬과 공식 순위 판정을 구분한다.
- Bronze·Silver·Gold 등의 등급 이름, 구간, 승급 조건은 참여 데이터 확보 후 결정한다.
- 시즌제는 장기 독점을 줄이는 후보이며, 시즌 길이와 초기화·이월 방식은 미정이다.

‘실시간 순위’는 영상의 실시간 판독을 뜻하지 않는다. **결과 확정 후 순위가 갱신되고, 최종 갱신 시각을 확인할 수 있는 것**으로 정의한다. MVP 완료 기준 후보는 정상 서비스 상태에서 결과 확정 후 60초 이내 반영이며, 규모·비용을 고려해 확정한다.

### 8.4 보상과 제재

| 사건 | 경쟁 결과 | 추가 처리 |
| --- | --- | --- |
| 도장 깨기 성공 | 도전 Box 승리, 레이팅 반영 | 도전 성공 이력·배지, 활동 포인트 후보 |
| 도장 지키기 성공 | 방어 Box 승리, 레이팅 반영 | 방어 성공 이력·연속 방어 배지 후보 |
| 정상 패배 | 레이팅 하락, 경기 이력 유지 | 완료 보상 가능. 정상 패배를 비매너 제재로 취급하지 않음 |
| 무승부 | 무승부 산식 적용 | 양측 완료 이력 |

| 부정행위·반복 노쇼 | 운영 정책에 따른 처리 | 경고·일시 제한 등, 사유와 이의 제기 경로 제공 |

## 9. 활동 포인트 사용과 운영 지속성

### 9.1 사용처 후보

| 사용처 | 기대 효과 | 조건·시점 |
| --- | --- | --- |
| Box 프로필 꾸미기 | 정체성과 성취 표현 | 초기 포인트 사용처 후보 |
| 지역 Box 소개·도전장 노출 | 신규 교류와 도전자 모집 | 확장 기능. 홍보 표시와 노출 한도를 명확히 적용 |
| 시즌 이벤트 참여·개설 | 지속적인 참여 | 이벤트 운영 능력 확보 후 |
| 제휴 체험·상품 혜택 | 오프라인 연결 | 제휴 계약과 비용 구조 검토 후 |

초기에는 한 가지 실제 사용처를 제공해 적립만 되고 소비되지 않는 포인트를 피한다. 프로필 꾸미기를 첫 후보로 두고, 실제 홍보 효과가 있는 노출 상품은 사용자 규모가 생긴 뒤 도입한다. 유료·포인트 홍보 영역이 공식 순위로 오인되지 않도록 화면을 설계한다.

### 9.2 포인트 운영 규칙

- 적립·차감 사유, 연결 경기, 처리 시각, 잔액을 내역으로 남긴다.
- 같은 경기 완료 이벤트를 중복 수신해도 중복 적립하지 않는다.
- 반복 상대·경기 취소·영상 미검증을 통한 포인트 획득을 제한한다.
- 부정 경기 보상 회수 시 이미 사용한 포인트의 처리 원칙을 정한다.
- 적립량, 일·주간 상한, 소멸, 취소·환급 정책은 개발 전 결정한다.

활동 포인트는 수익 자체가 아니다. 장기 수익 모델은 Box 운영 도구 구독, 표시가 명확한 홍보 상품, 제휴 이벤트 등을 후보로 검증한다. 유료 결제가 레이팅이나 판정 결과를 바꾸지 않도록 한다.

영상 저장·전송과 분쟁 검토에 운영 자원이 필요하므로, 파일럿에서 경기당 비용과 검토 시간을 측정한다. 외부 서비스 가격이나 시장 수요는 이번 문서에서 검증하지 않았다.

## 10. 주요 화면과 데이터 개념

### 10.1 화면 구성

| 화면 | 사용자가 할 일 |
| --- | --- |

| 경기 준비 | 합의 상태, 명단, 조건 잠금, 촬영·제출 기준 확인 |
| 기록 제출·검증 | 영상 업로드, 카운팅 입력, 상대 기록 검토, 이의 제기 |

| 운영 관리 | Box 확인, 신고·분쟁·결과 정정 처리 |

초기 일정 조율은 구조화된 조건 제안·수락으로 처리한다. 실시간 채팅, 영상 라이브 중계, 공개 소셜 피드는 별도 확장 기능이다.

이는 데이터 모델의 범위이며 실제 DB 테이블이나 기술 스택을 확정하지 않는다.

### 10.3 경기 상태

정상 흐름은 다음과 같다.

`도전장 공개 → 도전 신청 → 양측 합의·조건 잠금 → 경기 진행 → 기록 제출 → 검증 → 결과 확정 → 점수·순위 반영`

취소·만료·분쟁·무효는 별도 상태로 관리한다. 검증 중 이의가 발생하면 분쟁 상태로 이동하고, 운영자 판정 후 확정 또는 무효로 종료한다. 확정 결과의 변경은 정정 이력을 추가하는 별도 절차로 처리한다.

결과 확정과 점수 반영을 구분해, 반영 처리 실패 시 재시도할 수 있게 한다. 재시도로 레이팅이나 보상이 두 번 반영되어서는 안 된다. 적용 기한과 응답이 없는 상대의 처리 규칙도 각 상태에 필요하다.

## 11. 초기 제품 범위와 단계별 확장

### 11.1 초기 제품이 검증할 가설

**서로 교류 가능한 소수의 Box가 공정한 WOD 대결을 완료하고, 그 경험을 이유로 다시 도전한다.**

초기 제품은 폭넓은 기능 수보다 Box 등록부터 결과·순위 반영까지 한 경기를 끝낼 수 있는 흐름을 우선한다. 파일럿은 협조 가능한 실제 Box를 모집해 진행하고, 운영자가 등록과 분쟁을 직접 검토할 수 있는 규모로 시작한다.

### 11.2 MVP 포함 권고

- 사용자 가입, 역할, 주 소속 Box 관리.
- 최소 3명 위치 확인, Box 중복 검토, 운영 권한 확인.
- Box 대표 개인전과 한 가지 고정 구성의 단체전.
- 검토된 For Time·AMRAP 템플릿, 정의가 완료된 채점 조합만 지원.
- WOD 도전장, 신청·수락, 일정·장소 합의, 명단·조건 잠금.
- 한 장소 경기와 각자의 Box 경기. 동일한 합의·제출·검증 흐름 사용.
- 수동 카운팅, 영상 업로드, 양측 검토, 운영자 분쟁 처리.
- 부문별 Box 레이팅, 파일럿 지역 순위, 기본 승패·도장 이력.
- 활동 포인트 내역과 한 가지 사용처.
- 경기 일정·제출·판정 알림 및 최소 운영 관리 기능.

초기 개발 순서는 개인전으로 전체 흐름을 연결한 뒤 같은 구조에 고정 구성 단체전을 추가하는 안을 권고한다. 두 유형 모두 초기 제품 범위에 포함하되, 단체전 채점 정책이 미정이면 해당 유형은 공개하지 않는다.

### 11.3 후속 확장

| 단계 | 확장 후보 | 진입 조건 |
| --- | --- | --- |
| 2단계 | 자유 WOD, 여러 팀 구성, 친선전, 시즌·등급, 전국 순위, 홍보 노출 | 반복 경기와 판정 운영의 안정성 확인 |
| 3단계 | 개인 자유 매칭, 협동 WOD, 제휴 혜택, 세계 순위·다국어 | 참여 규모, 지역별 운영·지원 체계 확보 |
| 별도 연구 | AI 카운팅·동작 판정, 라이브 중계 | 비용·정확도·환경별 성능 검증 |

초기 제외 범위는 현금 보상·베팅, 포인트 거래, 지도 영토 점령, 모든 팀 조합, 모든 국가 동시 출시, 완전 자동 판정이다. 각각 추가 운영 규칙이나 기술 검증이 필요하기 때문이다.

## 12. 가설 검증과 성공 지표

| 지표 | 정의·확인 목적 |
| --- | --- |
| Box 활성화율 | 등록 시작 Box 중 위치·구성원·필요 확인을 마친 비율 |
| 첫 경기 완료율 | 활성화 Box 중 정해진 기간 안에 첫 확정 경기를 만든 비율 |
| 도전 수락률 | 유효 도전 신청 중 수락된 비율, 매칭 성립 여부 확인 |
| 재참여율 | 첫 경기 완료 후 정해진 기간 내 다시 경기에 참여한 Box 비율 |
| 경기 취소·미제출률 | 합의 이후 끝내지 못하는 원인 확인 |
| 분쟁 발생률·처리 시간 | 공정성과 운영 부담 확인 |
| 활동 분포 | 소수 Box에 경기·보상·순위가 집중되는지 확인 |
| 경기당 영상·검토 비용 | 운영 규모 확대 가능성 확인 |
| 운동 동기·만족도 | 참가자 설문으로 경쟁이 운동 참여에 도움이 되었는지 확인 |

기간과 목표값은 파일럿 설계에서 확정한다. 데이터가 없는 상태에서 임의의 성공률을 확정하지 않는다. 서비스 이용 증가와 실제 운동 빈도 증가를 동일하게 해석하지 않는다.

작업 지시서는 아래 묶음을 출발점으로 작성한다. 각 지시서에 **관련 문서 절·선행 결정 ID·입력/출력·예외 처리·검증 방법**을 연결한다. 결정되지 않은 값을 개발자가 임의로 채워 확정 정책처럼 구현하지 않도록 한다.

아래 완료 기준은 향후 개발 검증의 후보이며, 현재 완료되었다는 의미가 아니다.

| 작업 묶음 | 작업 목표 | 작업 방향 | 주요 작업 내용 | 완료 기준 후보 |
| --- | --- | --- | --- | --- |
| W-01 사용자·소속 | 참가 주체와 권한 구분 | 역할·소속 이력 보존 | 가입, 소속 승인, 관리자 권한, 이적 | 권한 없는 변경 차단, 이적 후 과거 경기 소속 유지 |
| W-02 Box 등록 | 실재하는 Box 단위 구성 | 3명·위치·운영 권한을 구분 | 확인 참여, 중복 후보, 운영 검토 | 2명으로 활성화 불가, 기준 충족 3명 확인 가능, 중복·GPS 오류 경로 확인 |

| W-05 수행·제출 | 판정 가능한 기록 수집 | 영상과 카운팅 연결 | 업로드, 재시도, 기록 입력, 제출 기한 | 재업로드로 기록 중복 생성 없음, 영상 열람 권한 확인 |
| W-06 판정·분쟁 | 신뢰 가능한 결과 확정 | 보류·판정·정정 이력 관리 | 상대 검토, 이의 제기, 운영 판정 | 분쟁 중 점수 반영 없음, 판정 근거와 정정 이력 확인 |
| W-07 레이팅·순위 | 성과를 일관되게 표시 | 부문·지역 분리, 재처리 안전성 | 산식, 변동 내역, 순위, 갱신 시각 | 승패·무승부·무효 예시 검증, 중복 반영 없음, 승인된 갱신 시간 충족 |
| W-08 포인트·성취 | 재참여 이유 제공 | 경쟁 점수와 사용 잔액 분리 | 적립 내역, 사용처 1종, 배지 | 포인트 소비가 레이팅에 영향 없음, 중복 적립·초과 사용 차단 |
| W-09 운영·알림 | 경기 완료를 지원 | 운영자가 예외를 처리 가능 | 마감 안내, 확인·분쟁 관리, 지표 | 미응답·미제출 처리 가능, 필수 운영 지표 집계 가능 |
| W-10 통합 파일럿 | 전체 경험의 성립 확인 | 실제 참가 흐름으로 검증 | 개인전·고정 팀전, 두 개최 방식, 예외 시나리오 | 등록→합의→제출→판정→순위·포인트 반영 완료, 분쟁·취소·정정 흐름 확인 |

각 지시서의 완료 기준은 사용자 관찰 결과와 데이터 일관성을 함께 확인해야 한다. 예를 들어 ‘순위 화면 개발 완료’ 대신 ‘확정 경기만 해당 부문·지역 순위에 한 번 반영되고 정정 후에도 내역과 일치한다’처럼 기술한다.
